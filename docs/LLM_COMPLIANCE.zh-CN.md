# AI/LLM 抽取：合规说明

> **本文不是法律意见。** 它记录的是出版社协议与平台政策**实际写了什么**，供你自行判断。
> 你所在机构的图书馆或法务部门才是权威依据。文末附免责声明。

本文档涉及的功能**尚未实现**。写它的目的是：让未来的抽取层从协议出发设计，而不是从技术便利出发。

## 核心分界线

在此之前的所有步骤，全文始终**留在你的机器上**。引入 LLM 带来了一个此前不存在的新问题：

```text
内容是否离开了你的机器？
```

这个答案几乎决定了全部风险，因此整体架构就是围绕它设计的。

| 方式 | 内容去向 | 评估 |
| --- | --- | --- |
| **本地模型**（Ollama、vLLM、llama.cpp） | 不离开本机 | **允许的路径**，见下文 |
| **外部/云端 API**（OpenAI、Anthropic 等） | 第三方厂商服务器 | **需要书面明确许可**，见下文 |

**默认走本地。** 外部 API 必须显式配置才启用。

## Elsevier 协议到底怎么说

以下是本项目所依据的两份文件。

### API 服务协议 §2.4 —— "Use with AI Systems; intermediary access"

**允许**结合 AI 系统使用，但该 AI 系统必须满足：

- 在**封闭托管（企业级）环境**中使用，仅供授权用户个人学术/研究使用；
- **不得用 Elsevier 内容训练外部 AI 系统的算法**；
- **不得与第三方共享，也不得让第三方访问** Elsevier 内容或其任何部分；
- 不得实质性或系统性地复制、保留、本地存储、再分发或传播 Elsevier 内容 ——
  **包括 AI 系统生成的回复**；
- 不得创建可能与 Elsevier 产品竞争、替代、或可反向还原出 Elsevier 产品的衍生作品或服务。

§2.5 补充：**你对所启用的任何可访问 API 服务的 AI 系统负责并承担责任。**

### TDM 条款 —— 决定性的一句

> "The ScienceDirect dataset and any TDM Output may be accessed, processed, or hosted by
> **third-party vendors retained by you only with the express written permission of Elsevier**
> and solely for the purposes as set out herein."

这句话直接决定了「本地 vs 云端」。把全文发送给商业 LLM 厂商，等于让该厂商成为
**处理 ScienceDirect 数据集的第三方供应商**。按此条款，**需要 Elsevier 的书面明确许可** ——
仅仅持有 API key 并不覆盖这一点。

### TDM 条款 —— 你**可以**做的事

> "text and data mine the ScienceDirect dataset via the API and **load and integrate the results
> (the TDM Output) on your internal system** for access by authorized users"

也就是说：**可以保留并整合的是「抽取产出（TDM Output）」，而不是原始数据集**，且需满足：

- **仅限学术研究用途**，不得商用。
- 对外分享 TDM Output 需附如下声明：
  > © Some rights reserved. This work permits academic research purposes only, distribution, and
  > reproduction in any medium, provided the original author and source are credited.
- **项目结束时必须立即永久删除 ScienceDirect 数据集的所有副本**（含备份）。TDM Output 可保留用于学术研究。
- 不得创建与 Elsevier 产品竞争、替代或反向还原的衍生作品。

### 其他影响设计的条款

- §2.1：**不得使用他人的凭证，也不得共享你自己的凭证。** 这就是为什么每个用户运行各自的本地实例、用各自的 key。
- 期限与终止：终止时须立即永久删除经 API 获得的所有内容副本，如被要求还需书面确认。

## 直接回答：付费全文 + 本地 LLM

**本地抽取付费内容属于允许的路径**，而它之所以允许，**正是因为内容没有离开你的机器**。
§2.4 与第三方供应商条款正是围绕这一点构建的。

有两点必须说清楚：

1. **「本地」必须是真正的本地。** 模型在本机运行、文档正文不经网络外发，才符合其本意。
   把同样的文本转发到云端端点，不会因为调用方是你自己的脚本就变得合规。
2. **开放获取（OA）是另一回事。** OA 内容（CC BY 等）不受上述限制，可以发送给外部 API。
   付费内容在没有书面许可前则不可以。

一处需坦诚说明的解读差异：§2.4 要求「封闭托管（企业级）环境」。
完全运行在你自己机器上的模型严格说并非 "hosted"，但它满足该条款**所有实质条件**
（无第三方访问、无外部训练），且比托管服务满足得更彻底。
若你希望针对自身情况获得确定结论，可询问图书馆：纯本地推理是否被他们视为符合 §2.4。

## 由此推导出的设计约束

以下是未来抽取层的硬性约束，而非建议。

1. **本地优先为默认。** 默认抽取目标为本地运行的模型。发行配置中不得预置任何指向云端的端点。
2. **云端须显式开启并加确认闸门。** 启用外部 API 前，用户必须确认其授权允许第三方处理。UI 必须在首次调用前用平实语言说明。
3. **云端默认仅限 OA。** OA 内容可使用已配置的外部 API；付费内容除非用户显式越闸，否则不得外发。
4. **绝不用内容训练。** 不得使用会保留输入用于训练的厂商层级；协议明确禁止外部训练。
5. **只发送最小必要内容。** 按相关段落/章节抽取，而不是整篇投喂。这同时降低法律风险、成本与幻觉面。
6. **每条产出都带溯源信息。** 每条抽取记录包含来源 DOI、章节、段落或图表、原文片段、置信度、
   抽取器版本，使结果可审计、可纠错。
7. **默认需要人工复核。** LLM 输出是「候选标注」，不是事实。未经复核不得进入数据库或论文。
8. **必须继续支持数据集删除。** `lit-harvest cleanup` 已能删除原始全文并保留派生结果，
   这正是 TDM 项目结束时的义务。抽取层不得另存一份原始数据集而绕过该机制。
9. **不接入 Sci-Hub 及同类来源。** 属于项目既定政策。把非法获得的内容喂给任何模型（无论本地或云端），
   只会叠加问题，而不是规避问题。

## 开放获取（OA）内容

对 OA 内容（CC BY、CC0 等），上述限制不以同样方式适用，因为许可本身已允许重用与处理。
常见条件是署名，部分许可还含「相同方式共享」或「非商业」条款。
请在抽取数据旁一并记录许可证，以便下游使用遵守。
